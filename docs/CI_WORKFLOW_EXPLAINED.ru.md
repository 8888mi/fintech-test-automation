# `tests.yml` построчно

Разбор файла [`.github/workflows/tests.yml`](../.github/workflows/tests.yml) — того, что
GitHub Actions выполняет на каждый push. Ниже его полная копия, где у каждой строки есть
комментарий. Рабочим остаётся только оригинал: правки в этой копии ни на что не влияют.

## Как читать YAML

- **Отступы — это структура.** Строка, сдвинутая вправо, принадлежит строке над ней.
  Отступ делается только пробелами, табуляция запрещена.
- `ключ: значение` — настройка. `ключ:` без значения — начало вложенного блока.
- `- ` в начале строки — элемент списка. В `steps:` каждый `- ` — отдельный шаг.
- `#` — комментарий, GitHub его игнорирует.
- `${{ ... }}` — выражение, которое GitHub подставляет во время прогона
  (имя ветки, результат шага, секрет и т. п.).
- `|` после ключа — дальше идёт многострочный текст; каждая строка — отдельная команда.
  Внутри такого блока `#` уже не комментарий YAML, а часть текста. Поэтому комментарии
  ниже внутри `run: |` и `path: |` — только пояснения для чтения: скопировать этот файл
  как рабочий нельзя.

## Файл с комментариями

```yaml
name: tests
# Имя workflow. Так он называется на вкладке Actions и в бейдже README.

on:
# Блок «когда запускать». Любое из перечисленных событий запускает прогон.
  push:
  # Событие «кто-то сделал git push»...
    branches: [main]
    # ...но только в ветку main. Push в другие ветки прогон не запускает.
  pull_request:
  # Открыт или обновлён pull request в любую ветку — тесты проверяют изменения до слияния.
  workflow_dispatch:
  # Разрешает ручной запуск: Actions → tests → кнопка «Run workflow».

concurrency:
# Правило «что делать, если прогоны наложились».
  group: ${{ github.workflow }}-${{ github.ref }}
  # Прогоны с одинаковой группой считаются конкурентами. Группа = имя workflow + ветка,
  # например «tests-refs/heads/main». Прогоны разных веток друг другу не мешают.
  cancel-in-progress: true
  # Новый прогон в той же группе отменяет ещё идущий старый — результат устаревшего
  # коммита уже никому не нужен, а минуты CI тратятся.

jobs:
# Список задач (jobs). Каждая задача выполняется на СВОЕЙ чистой виртуальной машине.
# Без указания зависимостей задачи идут параллельно.

  lint:
  # Задача №1: проверка кода линтером. Имя «lint» видно слева на странице прогона.
    runs-on: ubuntu-latest
    # На какой машине выполнять: свежий Ubuntu последней версии, который даёт GitHub.
    steps:
    # Шаги задачи. Выполняются строго по порядку; если шаг упал, следующие не запускаются.
      - uses: actions/checkout@v4
      # «uses» — взять готовый action (чужой переиспользуемый шаг). checkout скачивает
      # код репозитория на машину. Без него машина пустая. @v4 — версия action.
      - uses: actions/setup-python@v5
      # Готовый action, устанавливающий нужную версию Python.
        with:
        # «with» — параметры для action.
          python-version: "3.11"
          # Какую версию ставить. В кавычках, иначе YAML прочитает 3.10 как число 3.1.
      - run: pip install ruff==0.7.4
      # «run» — выполнить команду в терминале машины. Ставим линтер ruff, версия
      # закреплена, чтобы новая версия с новыми правилами внезапно не сломала CI.
      - run: ruff check src tests demo_service
      # Запускаем проверку трёх папок. Нашлась ошибка → команда вернёт код ≠ 0 →
      # шаг и задача lint станут красными.

  test:
  # Задача №2: сами тесты. Идёт параллельно с lint — они не зависят друг от друга.
    runs-on: ubuntu-latest
    # Снова отдельная чистая машина Ubuntu.
    timeout-minutes: 20
    # Если задача идёт дольше 20 минут — GitHub её убьёт. Защита от зависшего теста,
    # который иначе жёг бы минуты CI до лимита в 6 часов.
    steps:
      - uses: actions/checkout@v4
      # Скачать код репозитория.

      - uses: actions/setup-python@v5
        with:
          python-version: "3.11"
          # Python 3.11 — именно та версия, что указана в pyproject.toml.

      - name: Install Poetry
      # «name» — подпись шага в интерфейсе. Без неё GitHub показал бы саму команду.
        run: pipx install poetry
        # Ставим Poetry через pipx — он изолирует утилиту от проектного Python.

      - name: Cache virtualenv
        uses: actions/cache@v4
        # Action кэша: сохраняет папку между прогонами, чтобы не скачивать всё заново.
        with:
          path: ~/.cache/pypoetry
          # Что кэшировать: папку, куда Poetry складывает скачанные пакеты и окружения.
          key: ${{ runner.os }}-poetry-${{ hashFiles('**/poetry.lock', '**/pyproject.toml') }}
          # Ключ кэша = ОС + «отпечаток» (хэш) файлов зависимостей, например
          # «Linux-poetry-3fa9c1...». Пока poetry.lock и pyproject.toml не меняются,
          # ключ тот же и кэш подхватывается. Поменяли зависимости → новый ключ →
          # кэш собирается заново.

      - name: Install dependencies
        run: |
        # «|» — дальше несколько команд, каждая на своей строке.
          poetry install --no-interaction
          # Ставим зависимости проекта из poetry.lock. --no-interaction — не задавать
          # вопросов: в CI отвечать на них некому, прогон бы завис.
          poetry run playwright install --with-deps chromium
          # Скачиваем браузер Chromium для UI-тестов. --with-deps дополнительно ставит
          # системные библиотеки Linux, без которых браузер не запустится.

      - name: Start Kafka and the service under test
        run: docker compose up -d --wait
        # То же, что вы делаете локально: поднять Kafka и сервис платежей из
        # docker-compose.yml, в фоне (-d), дождавшись healthcheck (--wait).
        # Docker на машинах GitHub уже установлен.

      - name: Run tests
        run: poetry run pytest -n 4 --reruns 1 --reruns-delay 2
        # Запуск всех тестов:
        #   -n 4             — в 4 параллельных процесса (pytest-xdist); на машине GitHub 4 ядра;
        #   --reruns 1       — упавший тест перезапустить один раз (pytest-rerunfailures),
        #                      чтобы случайный сбой сети не краснил весь прогон;
        #   --reruns-delay 2 — перед перезапуском подождать 2 секунды.
        # Упал хоть один тест (и после перезапуска) → шаг красный.
        env:
        # Переменные окружения только для этого шага. Тесты читают их через
        # src/framework/config.py. Здесь они совпадают со значениями по умолчанию и
        # записаны явно, чтобы было видно, куда ходят тесты в CI.
          API_BASE_URL: http://localhost:8000
          # Адрес API сервиса платежей — контейнер из docker compose.
          UI_BASE_URL: http://localhost:8000
          # Адрес веб-страницы для UI-тестов — тот же сервис.
          KAFKA_BOOTSTRAP_SERVERS: localhost:9092
          # Адрес Kafka для тестов (внешний листенер брокера).

      - name: Collect service logs on failure
        if: failure()
        # «if» — условие запуска шага. failure() — «только если какой-то предыдущий
        # шаг упал». В зелёном прогоне шаг пропускается.
        run: docker compose logs --no-color > docker-logs.txt
        # Сохраняем логи контейнеров Kafka и сервиса в файл — по ним разбирают, почему
        # упало. --no-color — без цветовых кодов, чтобы файл читался как обычный текст.

      - name: Upload artifacts
        if: always()
        # always() — выполнить ВСЕГДА, даже если тесты упали. Результаты упавшего
        # прогона как раз нужнее всего.
        uses: actions/upload-artifact@v4
        # Action, который сохраняет файлы с машины в хранилище GitHub. Сама машина
        # после задачи удаляется, а артефакт остаётся.
        with:
          name: test-artifacts
          # Имя артефакта. По нему его найдёт задача publish-report, и под ним он виден
          # внизу страницы прогона (можно скачать zip).
          path: |
          # Какие файлы сохранить (список, по одному на строку):
            allure-results/
            # Сырые результаты Allure — из них потом соберут отчёт.
            docker-logs.txt
            # Логи сервиса. Если тесты прошли, файла нет — это не ошибка, GitHub
            # просто выдаст предупреждение.
          retention-days: 14
          # Хранить артефакт 14 дней, потом GitHub удалит его сам.

      - name: Tear down
        if: always()
        # Всегда, при любом исходе.
        run: docker compose down -v
        # Гасим контейнеры и удаляем тома (-v). Машину и так удалят, но так прогон
        # заканчивается аккуратно — как и локально.

  publish-report:
  # Задача №3: собрать отчёт Allure и выложить на GitHub Pages.
    needs: test
    # Ждать окончания задачи test (без этого стартовала бы сразу, параллельно).
    # От lint не зависит.
    if: always() && github.ref == 'refs/heads/main'
    # Условие запуска задачи:
    #   always()  — даже если test упал (иначе needs отменил бы задачу при падении);
    #   github.ref == 'refs/heads/main' — только для ветки main. Для pull request
    #   отчёт не публикуется, чтобы непроверенные изменения не попадали на сайт.
    runs-on: ubuntu-latest
    permissions:
    # Права автоматического токена GitHub (GITHUB_TOKEN) в этой задаче.
      contents: write
      # Разрешить запись в репозиторий — нужно, чтобы запушить ветку gh-pages.
      # По умолчанию токен может только читать.
    steps:
      - uses: actions/checkout@v4
      # Скачать код репозитория (стандартное начало задачи).
      - uses: actions/download-artifact@v4
      # Скачать артефакт, сохранённый задачей test (у этой задачи своя, пустая машина).
        with:
          name: test-artifacts
          # Какой артефакт брать — имя совпадает с upload-artifact выше.
          path: artifacts
          # Куда распаковать: получится artifacts/allure-results/ и т. д.

      - name: Keep report history
        uses: actions/checkout@v4
        # Тот же checkout, но теперь забираем не код, а прошлые отчёты...
        continue-on-error: true
        # ...и не падаем, если не получилось. На самом первом прогоне ветки gh-pages
        # ещё нет — без этой строки задача упала бы здесь.
        with:
          ref: gh-pages
          # Какую ветку скачать: gh-pages, где лежат опубликованные отчёты.
          path: gh-pages
          # В какую папку: ./gh-pages, чтобы не смешать с кодом из первого checkout.

      # Only the files are history; the checkout's .git must not travel on.
      # (Комментарий из оригинала: для истории нужны только файлы, служебная папка
      # .git переноситься дальше не должна.)
      - name: Drop git metadata from the previous report
        run: rm -rf gh-pages/.git
        # Удаляем служебную папку .git из скачанных отчётов. На первом прогоне там
        # оставался пустой git-репозиторий, который попадал в новый отчёт и ломал
        # публикацию ошибкой «src refspec gh-pages does not match any».

      - name: Generate Allure report
        uses: simple-elf/allure-report-action@v1.15
        # Сторонний action: собирает отчёт Allure и сохраняет историю прогонов.
        # v1.15 — версия; v1.7 перестала работать, т. к. её базовый Docker-образ удалили.
        with:
          allure_results: artifacts/allure-results
          # Откуда брать сырые результаты — из скачанного артефакта.
          allure_history: allure-history
          # Куда сложить итог: папка с отчётом этого прогона + всеми прошлыми.
          gh_pages: gh-pages
          # Где лежат прошлые отчёты (скачаны шагом «Keep report history») — из них
          # берётся история для графиков трендов.
          keep_reports: 30
          # Хранить 30 последних прогонов; более старые удаляются.

      - name: Publish to GitHub Pages
        uses: peaceiris/actions-gh-pages@v4
        # Сторонний action: коммитит папку в ветку и пушит её.
        with:
          github_token: ${{ secrets.GITHUB_TOKEN }}
          # Токен для push. GITHUB_TOKEN GitHub создаёт автоматически на каждый прогон,
          # вручную заводить ничего не нужно. Права на запись дал блок permissions.
          publish_branch: gh-pages
          # В какую ветку публиковать. Её же в Settings → Pages выбрали источником сайта.
          publish_dir: allure-history
          # Какую папку публиковать — ту, что собрал предыдущий шаг.
```

## Что дальше делает GitHub

После push в `gh-pages` GitHub сам запускает служебный workflow **pages build and
deployment**. Его нет в этом файле, он включается настройкой *Settings → Pages*. Он
выкладывает содержимое ветки на https://8888mi.github.io/fintech-test-automation/.
